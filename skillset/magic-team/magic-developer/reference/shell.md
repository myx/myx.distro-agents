# POSIX shell / AWK portability

Read this for any POSIX `sh`/AWK cross-platform portability question — writing or reviewing a script that must run unmodified on Linux, FreeBSD, and Darwin, regardless of which project it's for. Canonical home for this content; `magic-devops` reads this module directly rather than duplicating it, since it's the team's heaviest day-to-day user of it. [code-craft.md](code-craft.md) applies on top of this one for any shell code actually being written: straight-line, top-to-bottom, structure only where the code genuinely has structure.

## Principles

- **All three platforms are fully supported — none is a fallback or a lesser target**: FreeBSD carries the majority of the servers this software runs on; Darwin is the majority of its users; Linux is fully supported alongside both. That gives a non-portable construct two distinct worst cases: a FreeBSD break hits the largest number of servers, a Darwin break hits the largest number of people. The three named platforms mean their current versions — the latest LTS Linux, the latest RELEASE FreeBSD, a modern Darwin — and that set is a ceiling on effort as much as it is a floor on support: a construct that is sound on those three is portable enough, full stop. Don't contort code for an obsolete shell, an ancient utility or a long-superseded OS release, don't add compatibility shims for versions outside that set, and don't reject a clean construct because some historical version lacked it. Testing on whichever platform you happen to be developing on proves nothing about the other two — verifying a construct on Darwin and Linux does not establish it works on FreeBSD, and FreeBSD is where the servers are.
- **A file descriptor above 2 is not addressable as a path on all three platforms**: only `/dev/fd/0`, `/dev/fd/1` and `/dev/fd/2` are universal. Linux's `/dev/fd` is a symlink to `/proc/self/fd`, so every descriptor appears there; Darwin mounts `fdescfs` on `/dev/fd` by default, so it works there too; FreeBSD's stock `devfs` provides only those three, and anything higher needs `fdescfs` mounted on `/dev/fd`, which a stock install does not guarantee. So never hand a high descriptor to a tool as a path — `curl --data-binary "@/dev/fd/3"` is exactly this bug — either avoid it, or guard it with a fallback the way `remoteContext.Common` does: `if [ -r /dev/fd/3 ]; then . /dev/fd/3; else eval "$(cat <&3)"; fi`.
- **No external/GNU dependencies**: assume only what's on a bare Linux/FreeBSD/Darwin base install. No GNU coreutils-isms (`sed -i` without a backup-suffix arg, `ls --color`, `readlink -f` on Darwin), no assuming a package manager has run. If BSD/GNU flag behavior diverges, write to the POSIX-common subset or split into `.Linux`/`.FreeBSD` files rather than special-casing flags inline.
- **A "nothing found" result is evidence of absence only if a positive control ran first**: before trusting any recursive search's empty result, run the same command shape against a probe with a known answer and confirm it comes back — otherwise a genuinely clean tree and a search that never looked are indistinguishable, since both print nothing. The concrete trap: BSD `grep -r` on Darwin will not descend into a symlinked directory given as the search root unless the path carries a trailing slash, and will not follow symlinked subdirectories met during the walk; `-R` rescues neither case. A scan of a tree whose entries are symlinks into other filesystems therefore reports every file clean while having matched nothing anywhere — it never entered them, and the empty output looks identical either way. Use `find -L <root> -type f -exec grep ... {} +` for any recursive search over a tree that may contain symlinks: it follows both, and the trailing-slash difference stops mattering. Generalize past `grep` — any negative result offered as evidence needs a positive control through the same command shape before it counts as one.
- **Inline builtins beat scattered vars/subprocesses**: use parameter expansion (`${var%%pattern}`, `${var#pattern}`) and, in bash, `$'...'` quoting for a control character, inline — not a var declared then matched in `case`/`esac`, not a forked `printf`/`awk`/`head`. Smaller, faster, more readable. Also the non-fragile choice: a multi-line quoted string or heredoc embedding a literal control character is the most fragile shell construct there is — any autoformatter pass or reindent silently corrupts it, where `$'\n'` inline never can. (Separately, `$(...)` always strips trailing newlines — it can never hold "just a newline" for comparison; that's a correctness bug, not a formatting one.)
- **AWK: always put `;` before a closing `}` when a statement precedes it on the same line** (e.g. `{ f = x; print v > f; close(f); }`, not `close(f) }`). Treat as an axiom, not something to test-and-see: some non-Linux/non-gawk AWK implementations reject the missing-semicolon form as a hard parse error, even though it runs fine on a dev box's `/usr/bin/awk` ("the one true awk") — passing there proves nothing about the target fleet. Only a statement on its own line immediately before a `}` on its *own* line is safe without a trailing `;`.

## Reusable POSIX patterns worth knowing

- **Building a dynamic argv (env vars + binary + args) without `eval`**: POSIX `sh` only gives you one `$@` array. Lean on `env`'s own parsing: it treats each leading argv token matching `identifier=value` as an assignment and stops at the first token that doesn't match, then execs the rest — so `set -- "$@" "NAME=value"` to append pairs, then append the real binary's *absolute path* (can never look like `identifier=value` since it starts with `/`) and its args, and always invoke via `env "$@"` (harmless no-op prefix when there are zero pairs). No injection risk: each `NAME=value` is one argv token.
- **Portable mutex for a short critical section, no `flock`**: `mkdir` is atomic on every POSIX filesystem and `flock`/`lockf` aren't guaranteed present on bare FreeBSD/Darwin. For a lock held only microseconds (e.g. serializing writes to a shared stdout pipe), a tight-loop `mkdir "$lockDir" 2>/dev/null` retry (with a `sleep 1` fallback after some bound, purely as a deadlock guard) beats hunting for a portable `flock` equivalent. `rmdir` to release.
- **A hand-rolled wall-clock timeout with no GNU `timeout(1)`**: background the target directly (not inside a `( ... )` subshell, so `$!` is the real killable PID), run a watcher subshell that polls `kill -0` and does TERM-then-KILL after the deadline, then `wait` on the real PID in the foreground. Known tradeoff: PID-based, not process-group-based, so a grandchild the target forks (e.g. `curl`) isn't guaranteed to die with it.
- **Verify a `%`/`#`/`sed` filename trim against real names before trusting it**: a pattern like `${ITEM%.*}` (strip after the last dot) silently does the wrong thing the moment a real name contains a literal dot that isn't the suffix you meant to strip (found live: a command listing got mangled by exactly this). Grep the actual data for the separator character before shipping a trim heuristic.

## AWK mechanics that read as something else

- **`RS='\0'` does not slurp a file — it selects paragraph mode.** awk strings are NUL-terminated, so the assigned value collapses to the empty string, and an empty `RS` means paragraph mode. Measured on one-true-awk 20200816: `awk -v RS='\0' 'BEGIN{print length(RS)}'` prints `0`, and a 5-line file containing one blank line yields 2 records rather than 1. Paragraph mode additionally strips trailing newlines and skips leading blank lines, and that leading-blank skip silently shifts every byte offset the program reports — a splice driven by those offsets then writes to the wrong place. To read a whole file, rejoin the records under the default `RS` instead.
- **awk cannot see whether its input ended with a newline.** `doc = doc $0 "\n"` reproduces input that ended with one and adds one that was never there otherwise; `doc = (NR==1) ? $0 : doc "\n" $0` reproduces input that did not end with one and drops one that did. Neither is correct for both cases, so pick by what the consumer needs and say which one the program implements in its own header.
- **`awk -f prog.awk </dev/null` executes the program; it does not check it.** There is no syntax-only mode, and exit 2 covers a syntax error, a runtime error and the program's own usage guard identically — a sweep keyed on exit status cannot tell them apart, and reported five working programs as failures. Match stderr for `syntax error` instead.
- **`-v` performs backslash decoding on the assigned value; `ENVIRON` does not.** `-v x='C:\path'` loses the backslash before the program ever sees it, which corrupts a path and un-escapes exactly the sequences an earlier escaping stage just produced. Pass any value that can contain a backslash through the environment and read `ENVIRON["NAME"]`.

## Shell constructs that fail quietly

- **A bracket range is collation-dependent, so a range-based whitelist is not a whitelist.** Measured on this estate's Darwin box: `case "A" in [a-z])` matches under `en_US.UTF-8` and does not match under `LC_ALL=C`. Enumerate every accepted character explicitly, or pin `LC_ALL=C` around the test.
- **A tool's human-readable output is translated, so matching it is not a test.** `case "$out" in *"Already up to date."*)` suppresses git's no-op message under an English locale and matches nothing under `es_*` or `ru_*`, so the branch inverts and the quiet path becomes the noisy one on exactly the hosts nobody develops on. Nothing errors, and an English dev box cannot reproduce it. Compare machine-readable state instead — `git rev-parse HEAD` before and after, with `--quiet` on the command — or read the tool's own `--porcelain`/`--format` output, which is contractually stable. `LC_ALL=C` fixes the locale half but leaves the branch keyed on a message the tool is free to reword between releases, so it is a patch, not the fix. Generalizes to any command whose messages are localized.
- **`cmd ; rc=$?` under `set -e` never reaches the assignment** — the shell aborts on `cmd`'s own non-zero status before `$?` is read. `cmd || rc=$?` captures it, because `||` makes the command a tested one.
- **Command substitution resets `$?`.** `echo "$(basename "$f"): exit=$?"` reports `basename`'s status, not the status of whatever ran before it. Capture the status into a variable on a line of its own, before any substitution runs.
- **`$1` inside a function is the function's own first argument.** An expression written against the caller's `$1` and later moved into a function silently reads something else — three test sites were never exercised at all because of this. Pass the value in explicitly rather than letting a positional cross a function boundary.
- **`[ A -o B ]` becomes a 6-argument test the moment `$1` can be `!`, `(`, `=` or `!=`, and POSIX specifies nothing past four arguments.** sh, dash and bash all exit **2** with `too many arguments` there. `[ A ] || [ B ]` is two well-specified 3-argument tests and exits 1 cleanly, so the rewrite removes an unspecified-behaviour crash path rather than a style wart.
- **`dash` rejects `==` inside `[` by printing an error *and taking the false branch*** — a silently wrong branch in a `#!/bin/sh` script, not a loud failure. `=` is POSIX and behaves identically everywhere, FreeBSD's `/bin/sh` included.
- **`grep -w` treats a hyphen as a word boundary**, so `fgrep -w verbose` matches `very-verbose`. For membership in a space-delimited list use `case " $list " in *" $word "*)`, which compares whole tokens and forks nothing.
- **A function name containing a dot is not a POSIX identifier, and the parse failure takes the whole file.** dash, `/bin/sh` and `bash --posix` refuse to load a file that defines one; bash and zsh accept it. Because the parse fails before any line of the file runs, a compatibility shim inside that same file is impossible — the constraint has to be carried by documentation instead.
- **Caller text never lands in a `printf` format string.** A `%` in the data is read as a conversion specifier, so `printf "$msg"` errors or corrupts the output, and an unquoted `printf $@` silently drops every word after the first. Always `printf '%s\n' "$msg"`.
- **Command substitution returns when the capture pipe has no writers left, not when the command exits.** `x="$( cmd )"` therefore blocks for as long as *any* process still holds that pipe's write end, so a single background child the command leaves behind (`&`, a daemon, `nohup`) hangs the caller for that child's whole lifetime — reproduced live: an `execute` of `sleep 300 & echo STARTED-BG` froze an MCP server permanently, and every later request hung. The same defect is filed publicly against other agent tooling and documented for ksh93, so it is a property of the construct, not of one implementation. **Never run a caller-supplied or otherwise arbitrary command through `$( )`, process substitution, or a coprocess** — all three wait on pipe EOF. Redirect the command's output to a file, background it directly so `$!` is the real PID, and `wait "$pid"`: waiting on the process instead of the pipe is immune by construction. Where the caller controls the command text, `( exec >&- ; cmd ) &` is the fix — closing the inherited descriptor, not redirecting it, is what actually detaches a lingering grandchild.
- **`mv -f` carries the temp file's mode onto the target**, so a 0644 temp widens a 0600 file it replaces. Create the temp under `( umask 077 && … > "$tmp" )`, or `chmod` the temp — never the target — before the rename. Writing in place with `cat new > target` keeps the inode and therefore the existing mode and ownership, which a temp-plus-rename does not.
