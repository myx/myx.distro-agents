# `pwa-vision-iteration` — build the running PWA-architecture vision one facet at a time

The body of the section of the same name in this member's armed content.

Steps:
1. Pick one facet:
   - Read `PWA-VISION.md` at the skillset path in `MDLT_ORIGIN`. Every landed section is in that tree. A copy under a member or workspace folder can lag it.
   - Read the newest dated section's "Open threads for future passes" list, and take one item. That list is the menu as it stands. The seven facets this procedure once named are each answered by a section, and `Contents` names it.
   - List `magic-coordinator`'s inbox for items matching `pwa-vision`, processed items included. Treat a facet named by a queued or landed item as taken, and ignore an item marked withdrawn.
   - Read the `Idle-Tasks` entry's `min-interval` and `scope` in `magic-frontender.armed.md`. An item whose interval has not elapsed since the newest `pwa-vision` facet filing is not selectable.
   - A facet outside every open thread is a proposal to `magic-coordinator`, never invented here.
2. Think it through with the systems depth listed in Goals, building on the earlier sections of `PWA-VISION.md`.
3. File the new section, labelled `(draft)`, to `magic-coordinator` with `post-inquiry`. It lands in `PWA-VISION.md` by the skillset change rule.
   - A new section leads with its facet's menu name.
   - The new section carries every thread from the newest section's list that is still open, plus any this pass adds.
   - An architecture-boundary question (one app or several) goes to `magic-architect` with `post-inquiry` instead of being decided here. A disagreement with `magic-architect`'s own call is the no-quorum document, per "The ladder: one rung at a time".
   - `PWA-VISION.md` takes its own `maintainers:` line, or `magic-frontender`'s folder set where it carries none. Where that set names the team owner, the landing owes a propose-approve step above the maintainers' agreement.
